clircs version history

This records meaningful development builds. The early preview series is grouped by milestone where the surviving packages do not justify pretending every minor preview deserves a novel.

v0.8.61

Reified the inbound `SessionEvent` dispatch pipeline without changing its behavior. The former monolithic sequential method now executes an explicit, immutable six-stage order: admission and away state, protection and DCC, output routing, history storage, event delivery, and window completion. A small per-event context makes transformations and derived routing facts visible across phases, while explicit stop results preserve ignored-event, suppressed-output, and missing-window terminal conditions. The design intentionally avoids a class-per-stage hierarchy because the phases coordinate one application owner and have no interchangeable implementations. Added regression coverage that protects the architectural ordering contract.

v0.8.60

Added interactive XDCC pack requests without creating a second transfer subsystem. `/xdcc get <bot> <pack>` sends the conventional `XDCC SEND #pack` request; `/xdcc sget <bot> <pack>` requests `XDCC SSEND #pack` without any secure-to-plaintext fallback. Packs accept either `42` or `#42` input. The bot's resulting offer remains subject to the ordinary `/dcc accept` or `/dcc reject` decision and then uses the existing validated DCC transfer, progress, resume, cancellation, and collision-safe download path. XDCC requests do not open query windows or accept files automatically.

v0.8.59

Cleanup build. `/network profiles` now omits its redundant State column, labels Server(s) consistently, and displays each configured server on its own row. Continuation rows leave the profile, nickname, and SASL cells blank; unconfigured profiles remain visible as `[no server configured]`.

`/adduser` now describes its shorthand as `Usage: /adduser <handle> [hostmask|nickname]`. An unresolved or ambiguous nickname returns that same usage instead of exposing internal identity-resolution details. Undernet's `u2.*` server signature is recognized as Undernet ircu for advisory daemon compatibility metadata.

Removed the copy-pasted import block from all thirteen `ClientApplication` source files. Each partial now imports only the domains it actually touches and carries a concise responsibility comment aligned with `ARCHITECTURE.md`; the principal declaration owns the canonical XML summary. Added focused daemon, profile-presentation, and command-usage regression coverage. The Release solution builds with zero warnings. Windows Application Control blocked execution of both the newly compiled test assembly and the packaged transport assembly during final runtime verification.

v0.8.58

Settings-presentation cleanup build. `/cprot` and `/pprot` now show the effective protection state without repeating inheritance mechanics. The monitor-only safety override is represented directly as the protection state, personal protection no longer labels its sole response, and channel ban time appears only when kickban is the configured action.

`/network status` now concentrates on connection and saved-profile information: internal session IDs, case mapping, window counts, redundant advertised-network text, and the meaningless `Connected through: direct` line are gone. Saved profile status likewise omits internal profile IDs and learned network labels. Reconnect configuration is labeled accurately as a limit. Logging-rule columns now name network and target states explicitly.

Added focused protection-presentation regression coverage. The Release solution builds with zero warnings. All 321 runnable tests pass, with four environment-dependent Schannel tests skipped.

v0.8.57

Window synchronization architecture build. Removed the broad `_activityGate` and moved terminal selection, numbering, unread state, scroll offsets, and retained history behind an internally synchronized `WindowStateRegistry`. Live ring-buffer history no longer escapes the owner: redraw and scrolling consume immutable snapshots, with bottom-of-window redraw still copying and measuring only enough entries to fill the visible viewport.

A narrow `_windowTransactionGate` now exists only for operations that must coordinate a core IRC buffer with its terminal window. Event storage verifies that the destination buffer still exists while holding that transaction, and local close, confirmed PART, and ignored-empty-query cleanup remove core and terminal state together. This prevents late events from recreating orphaned window history and removes the earlier check-then-remove query race.

Automatic WHO and clone-scan correlation moved to `ChannelSynchronizationCoordinator`; timed bans, autojoin admission, and away acknowledgements moved to `SessionTransientState`. Output routing, join tracking, notification, DCC, and live-session registries rely on their own synchronization instead of being wrapped by an unrelated application lock. Recent connection settings are published as one immutable atomic snapshot.

Added concurrent activation, event-storage/viewport, away-acknowledgement, and channel-synchronization regressions. The Release solution builds with zero warnings. All 320 runnable tests pass, with four environment-dependent Schannel tests skipped.

v0.8.56

Scrollback performance build. Per-window history now uses ring storage, so reaching the 250,000-entry emergency ceiling and aging its oldest entries no longer shifts the entire retained history for every new IRC event. The existing one-day retention policy, 500-entry minimum, and lossless per-window ceiling remain unchanged. A separate 500,000-event application-wide emergency ceiling prevents several busy windows from multiplying memory use without bound; as with the existing resource boundaries, clircs disconnects the network producing the overflow instead of silently dropping live traffic.

Normal live redraw now walks backward only far enough to fill the visible viewport instead of copying and measuring the complete window history. Expensive total-row calculation remains limited to explicit scrollback navigation and nonzero-offset clamping. Incoming traffic while the user is scrolled up no longer rescans the entire history merely to maintain the current position.

Added regressions for constant-order front eviction, the application-wide history boundary, and a 250,000-entry viewport whose 30-row live view measures exactly 30 entries. The Release solution builds with zero warnings; all 316 runnable tests pass, with four environment-dependent Schannel tests skipped.

v0.8.55

Cleanup build. The Networks table now places its unnamed active marker between No. and Network, matching the established Active Windows layout. Removed the redundant explanatory sentence beneath Network Profiles.

v0.8.54

Added SASL EXTERNAL authentication for saved TLS network profiles. clircs now presents a configured TLS client certificate during the connection handshake, negotiates EXTERNAL through IRCv3 CAP and SASL, and sends the conventional empty authorization identity so the server can select the account associated with the certificate fingerprint.

Use /network sasl <profile> external <certificate.pfx> [required|optional] with a PKCS#12 .pfx or .p12 bundle containing both the client certificate and private key. The hidden prompt accepts its password or an empty password for an unencrypted bundle. Configuration validates that the bundle loads and contains a private key before replacing the existing SASL settings, and its confirmation displays the SHA-256 fingerprint for account registration. Certificate passwords are protected with Windows DPAPI in network-secrets.json; networks.toml stores only the mechanism, certificate path, and failure policy. Existing /network sasl <profile> <account> syntax remains compatible for PLAIN, with an explicit plain form also accepted.

The transport owns and disposes the loaded client certificate with the connection, rejects client certificates on plaintext endpoints, and keeps server-certificate validation unchanged. Profile, network, and SASL status output distinguishes PLAIN from EXTERNAL without exposing secrets. Added deterministic coverage for the EXTERNAL wire exchange, empty and explicit authorization identities, client-certificate propagation, and EXTERNAL profile persistence. The Release solution builds with zero warnings. All eight SASL negotiation tests pass; Windows Application Control blocked the newly compiled Clircs.Transport.dll during the broader local test run, so 278 of 316 tests ran successfully before packaging.

v0.8.53

Cleanup build. Active Windows now labels its first column No. to match Networks. Networks uses an unnamed active-marker column and labels the connected endpoint Server, so the two tables follow the same visual grammar.

WHO Name columns now share responsive width with long addresses instead of retaining an arbitrary 32-character ceiling. Both fields truncate only to fit the current viewport and recover their complete semantic text when the terminal is widened.

Channel topic events and the persistent topic bar now preserve traditional IRC bold, italic, underline, reverse, and color formatting while retaining plain text for measurement, wrapping, state, and logs. Debug windows can now be controlled by /logging and write daily raw-wire logs under each network's debug directory; because those logs are deliberately raw, they can contain passwords and reversible SASL PLAIN payloads.

Disconnecting or superseding a connection attempt now cancels its in-progress DNS and transport work. Issuing another /server command no longer waits for an unresolvable earlier address to time out before clircs can close that session. Added focused regressions for connection cancellation, topic formatting, responsive WHO names, and debug logging. The complete suite passes: 310/310 tests, with four environment-dependent TLS tests skipped.

v0.8.52

Added network-profile SASL PLAIN authentication over TLS. Configured connections now negotiate CAP LS 302, handle multiline capability advertisements and advertised mechanism lists, request SASL, complete the AUTHENTICATE exchange with correct 400-byte fragmentation, wait for authentication success before CAP END, and then finish ordinary IRC registration. Reconnects repeat the exchange with the current saved profile credentials.

Use /network sasl <profile> <account> [required|optional] to configure SASL through a hidden password prompt, /network sasl <profile> to inspect it, and /network sasl <profile> off to remove it. Required is the default and stops registration without automatic reconnect when the server lacks SASL or PLAIN, rejects the capability, completes registration prematurely, or returns a SASL failure numeric. Optional mode reports the problem and continues unidentified. Profile listings and status output show mechanism, account, policy, and credential availability without displaying the password.

SASL passwords are not written to networks.toml. They are stored in a separate network-secrets.json file as Windows DPAPI ciphertext scoped to the current Windows user, using the same shared Windows protection boundary now used by script secrets. PLAIN is refused on non-TLS endpoints. Secret-bearing option objects redact their password from diagnostic string conversion; raw /debug deliberately remains raw and therefore exposes the reversible Base64 AUTHENTICATE payload exactly as sent.

Added deterministic registration tests for successful authentication, reconnect authentication, missing capabilities under required and optional policies, rejected credentials, exact PLAIN payload construction, 400-byte fragmentation, raw-numeric suppression, profile policy persistence, plaintext exclusion, and DPAPI credential round trips. All six SASL negotiation tests pass. The Release solution builds with zero warnings; the final complete-suite rerun was partially blocked when Windows Application Control rejected Clircs.Transport.dll after 274 of 312 tests passed.

v0.8.51

Added the final emergency boundary to the lossless inbound flood architecture. Ordinary traffic is still never rate-suppressed: the circuit breaker remains dormant through up to 100,000 queued IRC events, 100,000 pending log entries, and 250,000 retained entries in one window. These deliberately high limits keep finite floods containing thousands or tens of thousands of lines on the normal lossless path.

If an endless hostile stream or stalled consumer reaches one of those hard resource limits, clircs opens one circuit for that network, disconnects it, drains work already accepted by the application, and reports the exact reason with manual /reconnect instructions. It does not silently discard traffic while pretending the connection remains healthy. A successful reconnect resets the circuit.

The event and logging queues are now explicitly bounded, and scrollback has a separate emergency ceiling above its normal Irssi-style age/minimum policy. Added regressions for explicit queue-capacity reporting, draining a completely full queue without deadlocking shutdown, and emergency scrollback trimming. The executable test runner completed all 280 tests that Windows allowed to load; the remaining 20 were blocked before execution because Application Control rejected Clircs.Scripting.dll.

v0.8.50

Changed ordinary inbound flood handling from suppression to lossless presentation. Channel messages, notices, actions, joins, parts, modes, topics, and other normal IRC events now continue through history, logging, scripts, and terminal output instead of being replaced by "suppressed excess events" summaries. Personal and channel protection remain separate policy systems and still inspect the complete event stream.

Inbound events are delivered to the terminal in bounded groups of at most 128. A group removes and restores the input, topic, and status rows once while retaining every individual IRC line, substantially reducing flicker and redraw overhead without making a large burst monopolize input indefinitely. Bottom-of-buffer event storage no longer remeasures the entire scrollback after every line.

Replaced the 500-entry ceiling with Irssi-style retention: clircs always keeps at least 500 entries and also keeps every entry from the most recent 24 hours, so a current flood containing thousands of lines remains scrollable. Logging no longer silently drops entries when its former 2,048-item queue fills; it accepts the complete stream and writes entries to disk in batches.

Added regressions for 5,000-entry recent scrollback, aging old history while retaining the minimum, bounded event-delivery batches, and a 5,000-line logging burst with exact first-to-last ordering. The final flood phase will add an emergency resource circuit breaker for traffic that exceeds sustainable client memory or disk capacity over time.

v0.8.49

Moved inbound IRC event delivery onto one ordered application queue. The socket reader can now continue accepting and parsing traffic without waiting for terminal presentation, while buffer state, protection processing, logging, scripts, and visible output still receive events in wire order.

Session shutdown drains already accepted events before removing that session's windows. Added a regression test that holds the presentation consumer still, injects 10,000 ordered events without blocking the producer, then verifies that every event is delivered exactly once and in order.

This is the flood-handling foundation build. Existing visible flood-suppression thresholds remain unchanged deliberately, so this build can isolate and test the event-ingestion change before later builds alter history, rendering, and suppression policy.

Empty lists use one concise message instead of an empty box, and raw MODE list requests receive the same formatting without request or synchronization chatter.

Channel list state now has one shared model instead of accumulating a separate mask collection and synchronization flag for every mode. Live list-mode changes update that same state, ban-clearing behavior remains compatible, and Solanum-style 728 quiet entries tolerate the additional mode parameter.

v0.8.45

Hardened terminal presentation against Unicode bidirectional override, embedding, mark, and isolate controls that could make hostile IRC text appear in a misleading order. Normal client output removes those invisible direction controls; the raw /debug window preserves their diagnostic value by displaying them explicitly as Unicode escape sequences. Documented that /debug intentionally contains exact IRC traffic, including credentials, and should be inspected before its contents are shared. Secure DCC certificate handling remains unchanged: traditional SCHAT and SSEND provide encrypted transport but no interoperable peer-identity convention, as already documented.

v0.8.44

Relaxed the automatic CTCP reply limiter after comparison with Irssi's established flood controls. A sender may now receive five automatic PING, VERSION, or TIME replies within ten seconds, while the network-wide limit is twenty replies in the same interval. This permits ordinary diagnostic sequences without allowing one sender or a distributed flood to turn clircs into an unrestricted NOTICE source. Added regression coverage for both limits and window expiry.

v0.8.43

Added the first client-level flood-resilience pass, separate from personal and channel protection. Ordinary outbound IRC traffic now permits a small burst and then follows a conservative send rate, while PONG, registration, and disconnect traffic retain critical priority. The outbound queue has explicit ordinary and critical limits instead of being able to grow without bound.

Automatic CTCP PING, VERSION, and TIME replies now have both per-client and network-wide limits, so one sender or a distributed botnet cannot turn clircs into a NOTICE flood source. Incoming chat, actions, notices, joins, parts, nick changes, modes, and topics pass through a separate client-survival guard after IRC state and configured protection have run but before terminal rendering, logging, and scripts. Excess events are replaced by a concise in-window suppression summary. Log buffering is bounded, and unsolicited private messages cannot create more than 100 automatic query windows per network session. Added focused regression coverage for ordinary and distributed flood shapes, output pacing, queue exhaustion, CTCP throttling, and query-buffer exhaustion. The full test suite remains green.

v0.8.32

Audited and tightened application orchestration and concurrency boundaries. Session events and command results now enter the application through one ordered delivery lane, preventing network callbacks and local results from concurrently mutating presentation, routing, and window state. The boundary remains deliberately synchronous and reentrant so related local events retain their natural order without adding an unnecessary queue or UI framework.

Each live network session now owns its background application work. Initial connections, reconnects, notify monitoring, synchronization, channel automation, protection actions, away acknowledgements, timed unbans, and automatic rejoins stop accepting new work during shutdown, and session disposal waits for accepted work to retire. Unexpected background failures are no longer silently abandoned: concise errors reach the session when possible and full details are written to logs/application-errors.log. Initial connection handling now suppresses only expected transport, TLS, timeout, protocol, and state failures instead of swallowing every exception. Added regression coverage for ordered event delivery, shutdown draining, late-work rejection, and background failure reporting.

v0.8.30

v0.8.29

Protection counters, ignore state, action reservations, and channel automation state are cleared with their owning network session; expired temporary state is pruned during ordinary use instead of accumulating until somebody inspects it.

Advanced /protect changes now write only the property the user changed, so channel and network overrides continue inheriting later changes from broader scopes instead of freezing a copied settings snapshot. Channel protection keys now use one stable stored representation with negotiated IRC case-folding as a compatibility lookup, preserving existing settings while making online and offline configuration agree. Removed the unused relaxed and strict preset machinery and replaced enum-position arrays with explicit detector defaults. Added regression coverage for per-network cleanup, atomic temporary reservations, sparse inheritance, and channel case-form compatibility.

v0.8.28

Small state files now share one durable writer that flushes a same-directory temporary file before atomically replacing the committed file, retains a complete backup where appropriate, removes abandoned temporary files, and coordinates with backup creation. Backup archives now read one stable committed generation and are fully reopened and read before being published.

Profile, trusted-certificate, logging, away-message, protection, user-directory, script permission, script load-state, script storage, and script-secret changes no longer leave live state ahead of disk after a failed commit. Malformed script permissions no longer prevent clircs from starting; the damaged file is reported and preserved while IRC and local-network access fail closed. Global client identity is now authoritative when connecting through saved profiles instead of repeatedly rewriting identity copies in every network entry. v0.8.27

Audited and rebuilt terminal window-state ownership. History, unread activity, window numbers, and scroll position now belong to one registry instead of four parallel dictionaries with separate cleanup rules. Window activation and removal now pass through that owner, including joins, cycles, session changes, ignored empty queries, and network shutdown. Command results captured for an inactive window remain in that window instead of leaking into the currently visible viewport. Removed the obsolete item-based paging implementation and the dead redraw-heading path. v0.8.26

Audited and rebuilt command execution and help ownership. Keyboard input, ordinary chat, and commands requested by scripts now pass through one serialized application-owned execution lane. Every invocation retains the network and window from which it originated, so a delayed script command cannot silently operate on whichever window happens to be active later. Results return to that captured context, with a network's status window as the safe fallback if the original window was closed.

Command definitions now own their usage, description, visibility, extended help, and optional topic help instead of making /help rediscover those rules through command-name conditionals. Hidden commands use the same metadata as ordinary commands. Quoted command arguments now preserve Windows backslashes while still supporting escaped quotes and backslashes, and command names may be separated from their arguments by any normal whitespace. Expected command failures remain concise; unexpected failures receive a restrained user message and a stack trace in logs/command-errors.log without recording command arguments or passwords. Added regression coverage for Windows paths, whitespace parsing, metadata ownership, context retention, and serialized execution.

v0.8.25

Audited and tightened the connection and network-session lifecycle. One live-session runtime now owns its IRC session, exact connection route, logical-network profile association, and reconnect operation instead of keeping those values in parallel dictionaries that could drift apart. Automatic reconnect now runs through a focused, testable loop; successful registration stops it, cancellation interrupts pending work, attempt limits are honored, and every retry retains the original endpoint and password.

v0.8.24

LIST and LINKS now share a network-query component that owns their multi-numeric result state and completion tables. Centralized session-event construction and server-text sanitization so extracted processors cannot quietly produce differently sanitized output.

IrcSessionProcessor remains the explicit protocol coordinator and the sole front door for incoming IRC messages, while NetworkSessionState remains the authoritative owner of network, channel, member, and buffer state. The processor dropped from roughly 1,850 lines to about 1,040 instead of being replaced with a reflective handler framework or another less obvious pile. v0.8.23

Stabilized IRC protocol processing and cross-network compatibility before 0.9. WHO and WHOIS requests now retain their own identities from the protocol processor through output routing, so overlapping requests return to the windows that issued them. LIST, LINKS, and WHOWAS now reject a second simultaneous request instead of silently merging replies whose numerics cannot be correlated safely. Closing a network session clears all pending output routes through one owner.

Negotiated IRC case mapping now governs pending WHOIS and WHOWAS state, notify and MONITOR state, and reconnect channel state, including safe reindexing when CASEMAPPING arrives or changes. Known 005 values are parsed and validated before either their raw or typed representations change, preventing malformed re-advertisements from leaving contradictory feature state. Unknown WHOIS extensions retain all significant parameters instead of dropping data. Added behavior coverage for overlapping requests, route cleanup, malformed 005 values, case-mapping changes, lossless WHOIS extensions, and representative ratbox, Solanum, Hybrid, Bahamut, ngIRCd, InspIRCd, and UnrealIRCd registration and WHOIS transcripts.

v0.8.22

Cleaned up commands and output before the next development stage. /autojoin, /ajoin, and /aj now share one implementation: a bare command adds the active channel, an explicit channel is accepted with or without add, and use outside a channel shows help. /rj mirrors the same shorthand for removal. Removed the redundant /version, /ver, and /fldprot commands while retaining /sv, CTCP VERSION, /cprot, and /pprot. Simplified DCC help around CHAT, SCHAT, SEND, and SSEND; detailed per-type help now explains passive and TLS behavior, and the obsolete --secure spelling is no longer accepted. Hid the low-level /protect command from the ordinary command list and removed its audit advertisements without removing the command itself.

Formatted numeric 443, removed punctuation from disconnect notices, removed the active-session legend from /network, and propagated confirmed self-nickname changes to the relevant windows on that network. User modes now appear beside the client nickname in every IRC status bar. /users now uses a readable table, /uwhois uses a WHOIS-style information box without exposing its internal record ID, and bare /adduser nickname derives the visible user's default hostmask with no automatic privileges. Added regression coverage for numeric 443 and network-wide self-nickname announcements.

v0.8.21

Audited the complete DCC request and transport lifecycle after adding secure transfers. Each request now owns its pending connection attempts and background transport work as well as its listeners, established sockets, timers, transfer state, and buffers. Canceling an outgoing connected CHAT now closes the actual connection; incoming and outgoing CHAT attempts can be canceled while connecting; session shutdown cancels and waits for related DCC work instead of leaving socket tasks behind. Runtime history pruning now covers incoming and outgoing requests without evicting live work. Tightened legal state transitions, removed late terminal-state rewrites, made secure CHAT status wording consistent, and added regression coverage for listener, sender, receiver, and connection-attempt cancellation.

v0.8.20

Added secure DCC file transfers using the established SSEND extension. /dcc ssend nickname file and /dcc send nickname file --secure originate active secure offers; --passive uses the existing reverse connection negotiation over TLS. Incoming SSEND offers can be accepted, rejected, canceled, and resumed through the ordinary DCC request commands without ever falling back to plaintext. Secure transfers retain collision-safe downloads, cumulative acknowledgements, live progress replacement, source and partial-file integrity checks, and coordinated lifecycle cleanup. Connection output reports TLS protocol and peer certificate fingerprints when supplied. Added active, passive, acknowledgement, and resumed secure-transfer coverage at the transport boundary.

v0.8.19

Added secure DCC CHAT using the established SCHAT extension. Active and passive secure chat share the hardened DCC lifecycle and negotiate TLS 1.2 or TLS 1.3 without silently falling back to plaintext. /dcc schat nickname and /dcc chat nickname --secure originate secure requests; incoming SCHAT offers use the ordinary accept and reject commands, including Eggdrop's CTCP SCHAT flow. Connection output reports the TLS protocol and peer certificate fingerprint when available while stating that legacy DCC peer identity is not verified. Obsolete anonymous-DH compatibility is deliberately excluded. SSEND offers are recognized but cannot be accepted or resumed until secure file transfer is implemented.

v0.8.18

Hardened the ordinary DCC stack before secure DCC work. DCC sockets now sit behind a stream transport boundary that can later carry TLS without duplicating CHAT and SEND. Consolidated each request's listeners, sockets, timers, buffers, and resume state under one runtime owner. Live requests can no longer be evicted by history trimming, and completion, cancellation, disconnect, and file finalization use one coordinated lifecycle. Partial downloads now carry network, sender, size, and filename metadata so clircs cannot resume the wrong same-named file; changed partials and changed outgoing source files are rejected. Malformed acknowledgements cannot claim unsent bytes. Added focused registry, cancellation-race, partial-integrity, source-integrity, transport, and acknowledgement regression coverage. Existing legacy partial files are preserved but are not guessed as resume candidates.

v0.8.17

Added traditional DCC RESUME and ACCEPT negotiation for active and passive SEND transfers. /dcc resume id finds an incomplete matching download, requests the exact byte offset, waits for the sender's acceptance, and continues writing and acknowledging from that position. clircs also validates and honors resume requests for files it is sending. Interrupted downloads remain as .clircs-part files for a later offer, while completed transfers retain collision-safe naming. Added parser, structured-event, storage, sender-offset, receiver-offset, and cumulative-acknowledgement coverage.

v0.8.16

Replaced per-second DCC SEND progress spam with one transient history entry per transfer. Progress updates replace that entry atomically across redraws, resizing, scrolling, and window changes; completion, failure, or cancellation turns it into the permanent final result. Transient progress is excluded from logs. Standardized user-facing canceling and canceled spelling and corrected stale DCC documentation before transfer-resume work.

v0.8.15

Added passive DCC CHAT and SEND negotiation. /dcc chat and /dcc send accept --passive, outgoing passive offers are paired with replies by their numeric token, and clircs connects back after the receiving client opens its listener. Incoming passive offers can be accepted normally; clircs opens the listener, returns the matching endpoint and token, then receives the connection. Active DCC remains unchanged. Added parser, matching, reverse-listener, IPv4, IPv6, filename, and transfer acknowledgement coverage. Secure DCC remains separate work.

v0.8.14

Completed the ratbox caller-ID and ACCEPT cleanup before passive DCC. /accept with no nickname now requests the list correctly. Numerics 456, 457, 458, and 718 have readable routed output, 281 and 282 remain a formatted list, and 716 through 718 use the caller-ID user mode advertised by the server instead of assuming +g. Successful ACCEPT changes remain silent because the server sends no confirmation.

v0.8.13

Cleanup between active and passive DCC work. Notify lists now use server-side MONITOR when advertised and retain silent batched ISON polling as the fallback. Added /accept for caller-ID mode, formatted ACCEPT and common permission numerics, made local and server-generated permission errors use the same wording, and removed trailing periods from newly normalized client messages. Passive DCC remains separate work.

v0.8.12

Added outgoing active DCC SEND with quoted filenames, large and zero-byte file support, cumulative acknowledgements, progress reporting, cancellation, expiry, and failure cleanup. Incoming DCC CHAT offers no longer open a DCC window merely to ask whether the user wants one; the active window gets a concise accept-or-reject notice, and a chat window opens only after acceptance. Terminal DCC requests are removed from /dcc list.

v0.8.11

Completed downloads never overwrite an existing file and default to the user's Downloads folder; dcc.downloads changes that location. Outgoing SEND and passive DCC remain unfinished. Active interoperability is covered by simulated socket tests but still awaits testing against another real client where routing permits it.
