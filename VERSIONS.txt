clircs Version History

v0.9.1

- Made window numbers contiguous and grouped by connection, closing gaps and keeping newly opened channels with their network.
- Separated Network and Profile in the Active Windows list and simplified its Window column.
- Added an optional connection lag meter with fixed-width values and warning colors.
- Added status-bar settings for the lag meter, TLS indicators, bouncer name, channel modes, user modes, and member totals.
- Limited Activity to half the status bar and added a count of additional active windows when the list does not fit.
- Removed the +Y member count from the channel status bar while retaining support for that mode elsewhere.
- Matched the default topic-bar colors to the status bar.
- Added /set startup on|off to control the automatic startup presentation at launch and on new connections.
- Added date separators for displayed history dates and live midnight changes, while suppressing separators triggered by server greetings.
- Added /uptime for local clircs runtime information and /uptime say to send it to the active conversation.
- Added a version-aware default quit message that can be restored with /set quitmsg default.
- Made /close --force use the configured quit message when closing a network connection.
- Rounded reconnect delay messages to whole seconds.
- Added logs to user-data backups.
- Added /backup restore with confirmation, complete data replacement, and recovery handling.
- Added encrypted saved server/bouncer passwords to network profiles.
- Added optional automatic acceptance of requested XDCC transfers, with commands to inspect and cancel pending requests.
- Added a separate raw script permission for /raw and /quote.
- Added script APIs for finding or creating windows and writing local output with IRC formatting or theme colors.
- Added input handlers for script-owned windows and text-mode script command arguments.
- Added a single permission-approval prompt when loading a script, with remembered approval and a new prompt for additional requested permissions.
- Removed the separate irc script permission for normal allowlisted IRC commands.
- Replaced /script list output with a compact table and made /script alone display usage.
- Integrated script command help and subtopics with /help.
- Added separate server-notice routing through snotice.output and standardized output-setting terminology on window.
- Renamed the caller-ID output setting to callerid.output.
- Made /set arrange settings into as many columns as the terminal width allows.
- Fixed info-box paging to preserve the original rows instead of repeating headings or dropping fields.
- Simplified manual /names output while retaining member totals for the automatic join list.
- Made failed WHOWAS lookups return a single readable line instead of a numeric and an empty info box.
- Corrected /help set validation for output and hostmask setting names.
- Changed wording and order of Network Status information.
- Fixed status bar flicker on Activity updates.
- Added standalone 301 handling for away replies outside of WHOIS.
- Temporarily removed official ZNC support. This follows unresolved ambiguity around server-time tags on the enabling CAP ACK. /reconnect tolerate remains available.

(Earlier version history records progress through development builds and is grouped by milestone. Sort of.)

v0.9.0

Network profiles can now manage multiple servers and per-profile usernames and user modes. Manual connections stay separate so they're not trying to pull in, or store info in, saved profiles.

Bouncer compatibility got a ton of work, and clircs now officially supports five: Lurker, soju, ZNC, shroudBNC, IRCCloud. Added support for certain IRCv3 capabilities so everyone plays together nicely: echo-message, message-tags, server-time.

Lots of other boring (but important!) stuff like tightening up DCC, limiting scrollback for better performance, encoding for UTF-8, formatting tweaks, and a whole bunch of bug fixes for connection and rendering and command issues.

v0.8.0 through v0.8.61

DCC joined the party, with CHAT and SEND, passive, IPv4 and IPv6, secure SCHAT and SSEND, and even a few XDCC capabilities (no server). DCC sockets, listeners, files, timers, buffers, and background work got explicit ownership, integrity checks, and coordinated cleanup.

Audited and rebuilt IRC protocol compatibility, response routing, connection and reconnect lifecycles, persistent configuration, command and help ownership, terminal windows, presentation, scripting, userlist and protection behavior, and application concurrency. The main `ClientApplication` source had become a monster, so it was split into domain partials, then durable runtime state was moved into dedicated session, DCC, routing, window, synchronization, transient-state, policy, and preference owners. Stateful numeric families gained focused processors, stable IDs and negotiated IRC case mapping became authoritative, and the inbound application pipeline became an explicit ordered set of inspectable stages.

Replaced visible inbound flood suppression with ordered lossless event delivery, batched terminal presentation, asynchronous logging, ring-buffer scrollback, and explicit emergency resource boundaries. Added bounded outbound scheduling and automatic CTCP reply limits separately from personal and channel protection. Added IRCv3 CAP negotiation, SASL PLAIN and EXTERNAL over TLS, Windows-protected credentials, structured channel list modes, MONITOR with ISON fallback, raw network debug windows and logging, responsive semantic tables and hyperlinks, traditional IRC input and topic formatting, asynchronous DNS cancellation, and terminal sanitization for hostile control and bidirectional text.

Then I put it on GitHub.

v0.7.0 through v0.7.6

Compatibility milestone! Started paying attention to server capabilities advertised through numeric 005 instead of making fixed ratbox assumptions. Added and corrected formatting for major IRCd families, WHO, WHOIS, WHOWAS, LIST, forwarding, account and hidden-host numerics, notices, and traditional IRC colors. Slow registrations gained a 60-second timeout. Reconnect cancellation, query behavior, and cross-network window handling were tightened during real, actual network testing. At length.

v0.6.0 through v0.6.2

Scripting becomes a thing. Added JavaScript addon loading through Jint, permissions, command registration, scoped events, private persistent storage, encrypted script secrets, remembered load state, and runtime limits. The musikcube example proved that a script could control an external program and contribute display content without adding musikcube-specific behavior to the core client.

v0.5.0 through v0.5.13

Focused work on connectivity and persistence: Added automatic reconnect with intentional, accidental, and KILL-aware behavior; saved connection routes and credentials; ZNC awareness; preserved windows across disconnects; network profiles; safer configuration writes and backups; daily logging; per-window input history; DNS lookup; and numerous connection-state corrections found through dogfooding.

v0.4.0 through v0.4.25

Did a bunch of terminal work, formatting, and user protection stuff. Added the full-screen redrawable viewport, stable numbered windows, status and topic bars, unread activity, some themes, formatted WHO and WHOIS output, channel and personal protection, userlists, clone detection, network-scoped channel settings, settings help, and the current command-oriented interface.

v0.3 development series

Established a technically functional IRC client with Windows console input, server connections, TLS certificate handling, multiple network sessions, channels and queries, core convenience aliases, local echo behavior, autojoin profiles, membership state, basic formatted server output, and early theming.

v0.idea-in-my-head through v0.2

I assume most IRC clients start out the same way this one did, by putting together the architecture and command parser and protocol framing and all that, just trying to get it to connect, join a channel, and send a message. That's what happened here. Not a lot to write home about here.
